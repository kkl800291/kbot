# 习惯记忆与人格偏移

日期：2026-11-10（修订：习惯长期保存、事件接线、模型改写开关）

KBOT 继续用现有本地时钟决定何时休息、喝水和主动说话。本设计在旁边增加本机习惯记忆，并让性格在用户选定的底子上缓慢偏移。习惯由计数按天折算、长期保存，在设置里可见、可单条删除。模型只负责把已经算出的结果说成短句。

## 目标

- 长期记住相处中形成的节奏：连续工作多久会停、提醒多半被怎样回应、夜里是否仍在、主动陪伴是被点开还是被放过。
- 用户几天不用电脑或出差两周，习惯不会因此消失；只有新的相处持续指向相反方向，或用户手动删除，习惯才变化。
- 人格以用户选择的可爱、温柔、活泼或安静为底，按习惯每天最多偏移一档。
- 工作时长、离开、休息和发言预算仍由现有算法决定。学到的工作时长不改写「每工作 N 分钟休息 M 分钟」。

## 非目标

- 不接入 AstrBot、QQ 或向量记忆。
- 不让模型撰写、新增或覆盖习惯。
- 不记录聊天原文、窗口标题或具体应用名。
- 不修改用户设置里的说话频率。偏移只能让低优先级陪伴更晚、更短，不能更早。
- 不把用户亲口确认的偏好并进习惯；那条确认卡流程保持原样。
- 不改提醒的触发时间、优先级和文案。

## 数据

全部写入现有 `state.json`，由主窗口持有。设置窗口只读快照并发送删除或重置。

### 相处记录 `journal`

短期原始记录，只用于下一次折算和设置里的「还差多少次」。每条 `{ id, t, type, ... }`，只保留最近 14 个本地日。类型：

- `work`：`minutes`，`end` 为 `rest` 或 `away`。一段工作因开始休息（`startRest`、「跳过这次」不算），或 `ActivityClock` 因离开达到休息阈值调用 `resetWork` 而结束时写入。间隔超过 10 秒的跳跃不计入，短于 1 分钟不记。
- `reminder`：`kind`，`action` 为 `accepted`、`snoozed`、`skipped`、`muted` 或 `ignored`。覆盖内置休息、喝水、护眼、用餐、下班、深夜提醒和用户自设提醒。早安、节气、生日这类 `speech` 不算提醒。
- `companion`：`action` 为 `opened` 或 `expired`。只记真正以气泡显示过的主动陪伴（含「欢迎回来」）。气泡没有关闭按钮，所以只有这两种结果。
- `presence`：`day`（本地日期）和 `night`（布尔）。每个本地日每个小时内，用户非空闲（空闲不足 60 秒）时最多记一条。`night` 在写入时按当时的 `S.params.nightAt` 判断：本地时间不早于 `nightAt` 或早于 05:00。

### 事件接线

`bubble.js` 的 `dismiss` 改为携带明确原因，并把事件对象一起发出：`A.emit('bubble:dismiss', why, b.ev)`。原因固定为：

- `action`：点了气泡上的按钮
- `open`：点主动发言气泡打开聊天（现在走默认 `action`，要改）
- `expire`：自然淡出
- `preempt`：被更高优先级顶掉
- `hide`：`hide`、`hideSpeech`、`takeover` 等系统收起（现在走默认 `action`，要改）

现有 `budget.ignored` 的行为保持不变：只有 `expire` 加一，其余原因清零。

需要记录的事件在 `ev.track` 上标注 `{ type: 'reminder' | 'companion', kind }`。记录规则：

- 提醒：按钮各自在 `fn` 里记 `accepted`、`snoozed`、`skipped` 或 `muted`。目前普通提醒和自设提醒的「好的」没有 `fn`，需补上只做记录的 `fn`。休息提醒的「好的，去休息」记 `accepted`。`bubble:dismiss` 原因为 `expire` 时记 `ignored`。`preempt`、`hide` 不记。
- 陪伴：原因为 `open` 记 `opened`，为 `expire` 记 `expired`。其余不记。
- 面板开着时提醒经 `A.chat.pushPro` 进聊天。用户点了按钮照常记录（同一个 `fn`）；没点不记，不推断为忽略。
- 勿扰、角色隐藏、离开、聊天或设置正开着因而没显示的话，什么都不记。

### 习惯 `habits`

固定四种，标识稳定。每种保存一个长期累积器，而不是每次从 14 天记录重算：

- `work-stretch`：`{ minutes, samples }`
- `reminder-tolerance`：`{ yes, no, samples, side }`
- `night-presence`：`{ nightDays, activeDays, samples, on }`
- `companion-reception`：`{ yes, no, samples, side }`

另存 `updatedAt`。`samples` 是累计、不衰减的样本数，只用于判断「攒够没有」和在设置里展示。

### 折算时机

每个本地日只折算一次：主窗口启动时，以及 `tick` 发现日期变化时，把 `foldedAt` 之后、今天 0 点之前的记录按天依次折入累积器，然后把 `foldedAt` 设为今天 0 点。今天的记录要到明天才进入习惯。

### 折算规则

衰减只在「有新记录的那一天」施加，用户不在的日子不衰减，因此长期不用电脑不会让习惯变淡或消失。

- `work-stretch`：当天 `work` 的中位数为 m（偶数个取中间两数平均，四舍五入）。首次 `minutes = m`，之后 `minutes = round(0.7 × minutes + 0.3 × m)`。`samples` 加上当天条数。`samples >= 5` 时可见：「连续工作大约 N 分钟后会停一下」。
- `reminder-tolerance`：当天 `accepted` 计为 yes，`snoozed`、`skipped`、`muted`、`ignored` 计为 no。`yes = 0.9 × yes + 当天 yes`，`no` 同理。比例 r = yes / (yes + no)。`samples >= 8` 后：没有方向时，r >= 0.6 设为照做，r <= 0.4 设为放过；已有方向时，只有越过另一侧阈值才翻转，落在 0.4 到 0.6 之间保持原方向。照做：「提醒大多会照做」。放过：「提醒经常被延后或放过」。
- `companion-reception`：`opened` 计为 yes，`expired` 计为 no，衰减、阈值和滞回同上。点开：「主动陪伴经常被点开」。放过：「主动陪伴经常被放过」。
- `night-presence`：当天有任意 `presence` 时，`activeDays = 0.9 × activeDays + 1`；当天有 `night` 为真的记录时，`nightDays = 0.9 × nightDays + 1`，否则 `nightDays = 0.9 × nightDays`。`samples` 为累计夜间天数。`samples >= 5` 且 nightDays / activeDays >= 0.4 时出现；已出现后降到 0.2 以下才消失。说明：「夜里 nightAt 后仍常在」，文案里写入当时的设置时间。

说明句由模板生成，不经模型。

删除某条习惯：该习惯的累积器和 `samples` 清零，`foldedAt` 之前的记录本来就不再参与，因此必须用删除之后的新记录重新攒够。

### 人格偏移 `drift`

底子仍是 `S.persona`。偏移只有两个整数：

- `talkativeness`：-2 到 2
- `nightQuiet`：0 或 1

原设计里的「语气轻重」删除：本地只能在现有句子里挑长短，效果和话多话少重复，信号来源也相同。

目标值只从当前可见习惯推出：

- 陪伴常被点开、提醒大多照做各算一个话多信号；陪伴常被放过、提醒常被延后或放过各算一个话少信号。只有话多信号时目标为信号个数（最多 2）；只有话少信号时为负的信号个数（最少 -2）；两种都有或都没有时为 0。
- `night-presence` 可见时 `nightQuiet` 目标为 1，否则为 0。

偏移在每日折算之后走一步：两个数里最多只动一个，只向目标移动一档；都需要移动时先动 `nightQuiet`。不再需要 `stepDay`、`stepUsed`，因为折算本身每天只发生一次。习惯被删除后目标随之变化，偏移逐日退回。

「恢复默认语气」把两个数清零，不删除习惯，也不改 `S.persona`。当天不再折算，所以从下一个本地日起再按每天一档靠近目标。用户改性格底子时，习惯和偏移都保留。

## 谁读取

- 休息、喝水等提醒的触发时间、优先级、文案和按钮保持现有逻辑。
- 主动陪伴的基准间隔仍是 `companionDelay(S.freq)`。`talkativeness` 为负时，下一次低优先级陪伴额外再等 |talkativeness| 个基准间隔。`SpeechBudget` 的 `ignored` 退避是短期的（任何互动清零），偏移是长期的，两者叠加；为避免叠加过度，单次陪伴的总等待不超过基准间隔的 3 倍。正值不缩短间隔。
- 选句只用现有 `CompanionVoice` 文案。`nightQuiet = 1` 且当前时间处于 `nightAt` 之后的夜里时，陪伴句改从 `quiet` 池里选。其余时间：`talkativeness` 为正偏向当前性格池里较长的一半，为负偏向较短的一半，为 0 时维持现状。
- 聊天系统提示在现有性格和记忆之后附上可见习惯的说明句与偏移的中文描述。`S.send.memory` 关闭时，提示里不放习惯和偏移；本机选句仍然使用它们。模型上下文中的习惯标记为参考，不能据此声称又记住了新内容，也不能调用工具去写习惯。

### 模型改写主动陪伴

- 新增设置 `S.aiCompanion`，默认关闭，放在 AI 页。说明写明会按说话频率定期请求模型。
- 开启且有可用对话模型时，到点先选好本地句，再发一次改写请求：带性格、偏移描述、本地句；`S.send.memory` 打开时才附习惯说明。请求不带工具、不重试，超时 8 秒。
- 请求在途期间不安排新的陪伴（`nextCompanionAt` 推到超时之后）。返回时重新检查现有的 `blocked` 条件、`A.away` 和发言预算：任一不满足就丢弃这一句，按 30 秒后重试的现有规则继续，不排队补说。
- 失败、超时或返回空文本、超过 60 字时，直接说那句本地句。`A.chat.generating` 为真时不发改写请求，直接用本地句。

## 设置

主窗口快照增加 `habits`（可见习惯的说明、样本数、更新日期）、`drift`，以及 `habitProgress`（四类各自已累计的样本数加上今天未折算的条数，和所需次数）。原始记录不进设置窗口。设置窗口沿用现有字段差分，不自己写 `state.json`。

允许的新操作：

- `removeHabit(id)`
- `resetDrift()`

界面：

- 角色页性格卡片下显示一行现状。两个数都为 0 时写「语气还和你选的性格一致」。否则组合短句，例如「最近话少一点，夜里更安静」。旁边是「恢复默认语气」。
- 记忆页在「我记得的」下面增加「相处里养成的习惯」。没有习惯时说明仍在观察，并写出四类各自还差多少次；今天的记录要明天才会算进去。有习惯时显示说明、样本数和更新日期，只能删除。
- AI 页增加「让模型说主动陪伴的话」开关。
- 「清空全部记忆」只清空 `memories`。
- 「清除所有数据」仍是整份状态清空并重新加载，相处记录、习惯和偏移一起消失。

## 失败

- 习惯、偏移、`foldedAt` 或相处记录缺失、类型不对或超出范围：启动时该部分按空值处理，其余状态照常加载。现有损坏文件的 `.recovery` 备份保持不变。
- `foldedAt` 晚于当前时间（系统时间回拨）：不折算，把 `foldedAt` 设为今天 0 点。
- 模型不可用或请求失败：主动发言使用本地句子。失败本身不记成相处记录；气泡之后被点开或过期，仍按陪伴结果记录。
- 保存失败沿用现有磁盘空间提示，不另造一套错误。

## 测试

用现有 Vitest 测纯函数和接线，不请求真实模型。

- 折算：4 条工作记录不产生 `work-stretch`；第 5 条折入后产生，首日 N 为中位数，次日按 0.7/0.3 更新。
- 提醒：8 条里照做比例在 0.4 到 0.6 之间不产生习惯；6 次延后加 2 次照做产生「经常被延后或放过」；已是放过方向时比例回到 0.5 不翻转，到 0.6 以上才翻转。
- 长期保存：习惯形成后连续 30 个本地日没有任何记录，再折算时习惯和比例不变。
- 删除习惯后累积器清零，需要新的 5 或 8 条才会再现。
- 每天只折算一次：同一天重复启动不重复折入；跨三天未启动时三天依次折入。
- 偏移：每次折算最多动一个数一档；两数都偏离目标时只动 `nightQuiet`；恢复默认语气后当天保持全 0。
- 间隔：`talkativeness` 为 -1 时多等一个基准间隔；与 `ignored` 退避叠加不超过 3 倍；为 2 时不比 `companionDelay` 更早。
- 选句：夜里且 `nightQuiet = 1` 时陪伴句来自 `quiet` 池；提醒文案保持原句。
- 事件：点开气泡记 `opened`，淡出记 `expired`，`preempt` 和 `hide` 不记；普通提醒「好的」记 `accepted`，淡出记 `ignored`。
- 损坏的习惯字段被忽略后，空累积器仍能折算。
- 超过 14 个本地日的原始记录被丢弃，但已折入的习惯不受影响。
- `send.memory` 关闭时，系统提示和改写请求都不含习惯说明。
- 改写：模型函数抛错或超时时，主动发言等于预先选好的本地句；请求返回时面板已打开则不说话。
